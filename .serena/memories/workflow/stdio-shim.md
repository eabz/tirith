# The stdio shim (`tirith stdio`)

- `src/stdio.rs`: `ensure_daemon(root, bind)` canonicalizes `root`, reads `.tirith/runtime/daemon.json`, GETs `{dashboard_url}api/health` (1s timeout) and parses `{ok, version, root}`. Three outcomes (ADR-0016): the daemon serves another root -> foreign, never signalled, the shim starts its own daemon; both the recorded and the reported version equal the crate version -> reuse; otherwise -> `stop_daemon` (SIGINT on unix via `kill -INT`, `taskkill /F` on windows; waits up to `STOP_TIMEOUT` 10s for the PID to be gone via `ps -o stat=` (zombie = gone), never starts a replacement while it lives; clears daemon.json only if it still names that pid), then start. Spawned daemons are handed to a reaper thread (`reap`). `start()` spawns `current_exe() serve --root <root> --bind <bind>` detached (output appended to `.tirith/runtime/serve.log`) and keeps the `Child` only to `try_wait()`: an immediate exit (port taken) triggers one retry on `127.0.0.1:0`. Polls up to 15s for a non-foreign healthy daemon.
- `run()` then connects an rmcp HTTP client to the daemon and serves a `Proxy: ServerHandler` over `rmcp::transport::stdio()` forwarding `tools/list` and `tools/call`.
- Every restart, refusal, and fallback is logged to serve.log with a `[tirith stdio]` prefix; that is what the tests assert on.
- `/api/health` (src/dashboard.rs) reports `root` from `DashboardContext.repo_root`, which `tirith serve` canonicalizes in cli.rs. Daemons older than that report no root and are assumed to be ours.
- The shim does not start the menu bar tray; `tirith serve` does (`tray::launch_if_absent`, skipped with `--no-tray`) and registers the daemon in the per-user registry (ADR-0019).
- `.mcp.json` / `.cursor/mcp.json` register `tirith` as `command: tirith, args: [stdio]` (Serena-style). After `cargo install --path .` nothing needs stopping: the next session's shim replaces the old daemon.
- Tests hold a `DaemonGuard` per temp repo whose Drop SIGINTs the recorded pid (then SIGKILL after 3 s), so no `tirith serve` leaks even when an assertion fails; verify with `ps | grep "tirith serve"`.
- Tests: `tests/stdio_shim.rs` spawns `CARGO_BIN_EXE_tirith stdio --root <tmp> --bind ...`, speaks raw JSON-RPC over pipes. Cases: start + proxy + second shim reuses; record says 0.0.1 -> old daemon stopped cleanly and replaced; record with dead pid/closed port -> replaced without a signal; record pointing at another repo's daemon -> that daemon untouched, own daemon started on an ephemeral port after the bind on its address fails. A daemon is a real `tirith serve` child; the version case is faked by editing daemon.json's version, which the shim compares alongside the health version.
- ADR-0006 (start on demand) and ADR-0016 (replace stale, refuse foreign) document the decisions.
